# Handoff: «Арена Работы» — платформа сезонных смен на карте

## Overview
Веб-платформа, где работодатели (подрядчики, УК, частные лица) публикуют разовые сезонные смены точкой на карте (уборка снега, покос, благоустройство, стройка), а исполнители находят их рядом с базой, откликаются, получают найм, общаются в чате, сдают работу и получают оценку. Оплата идёт **напрямую между сторонами** — платформа деньги не проводит и споры о деньгах не разбирает.

Задача Claude Code: **реализовать продукт целиком — фронтенд по прототипу и бэкенд** (данные, авторизация по SMS, чат, модерация, уведомления).

## About the Design Files
Файлы в `design/` — **дизайн-референсы в HTML**: интерактивный прототип, показывающий внешний вид и поведение. Это **не production-код** — логика в нём демонстрационная (данные в памяти/localStorage, SMS-код всегда `1234`, пароль не проверяется). Нужно **воссоздать интерфейс в выбранном стеке** и написать настоящий бэкенд.

Рекомендуемый стек (если нет своего): Next.js + TypeScript на фронте; Postgres; бэкенд — Supabase (Auth по телефону, Realtime для чата, Storage для фото) **или** свой Node/NestJS. Требование 152-ФЗ: персональные данные граждан РФ хранить на серверах в РФ — Supabase self-hosted / Yandex Cloud / Selectel.

Открыть прототип: `design/Арена Работы — прототип.html` (один файл, нужен интернет для карты и шрифтов). Демо-вход: `daniyar_s` (исполнитель) / `aigul_t` (работодатель), любой пароль ≥ 6 символов. Исходник: `design/Сезон - платформа v5 (тихий интерфейс).dc.html` — шаблон + класс логики `Component` (всё поведение описано там, методы названы по действиям: `apply`, `hire`, `reportDone`, `accept`, `noShow`, `openCancel`, `publish`, `badWordIn` …).

## Роли и аккаунты (важно)
- **Один аккаунт — одна роль** (`freelancer` | `employer`). Роль выбирается при регистрации и закрепляется. Для второй роли нужен отдельный аккаунт с другим телефоном и логином.
- При входе роль не выбирается — кабинет открывается в роли аккаунта.
- Вход: **логин или телефон** + пароль. Определение: строка из `[+\d\s()-]` → телефон (≥ 10 цифр, сравнение по последним 10), иначе логин.
- Гость видит карту, ленту, карточки заказов без регистрации. Профиль нужен для отклика/публикации; после регистрации отложенный отклик отправляется автоматически.
- Админ-панели в первой версии **нет**.

## Регистрация (4 шага)
1. **Роль**: Исполнитель («Ищу сезонные смены рядом с домом») / Работодатель («Публикую заказы и нанимаю людей»).
2. **Контакты** — все поля обязательны:
   - Имя и фамилия (≥ 2 символа); у работодателя «Контактное лицо».
   - Телефон (≥ 10 цифр) — **единственная проверка личности**, код по SMS; номер подходит для входа.
   - Логин: `^[a-zA-Z0-9._]{3,20}$`, недопустимые символы не вводятся.
   - Пароль ≥ 6 символов.
   - E-mail (валидный) — для чеков и уведомлений.
   - Город (база).
   - **Проверка уникальности на этом шаге**: занятый телефон/логин (в любой роли) → ошибка у поля «Этот номер уже зарегистрирован — как исполнитель. Один аккаунт — одна роль: войдите или укажите другой номер.»
3. **Профиль**: исполнитель — навыки (+свои), свой инвентарь (+свой), свой транспорт, города работы; работодатель — тип (частное лицо/организация), название/ИНН, как попасть на объект, инвентарь.
4. **SMS-код** (4 цифры), таймер повторной отправки 60 с, альтернативный канал (звонок), галочка оферты + согласия на обработку ПДн обязательна.

Проверки ИНН, паспорта и самозанятости **нет** — убраны намеренно.

## Восстановление пароля
Логин или телефон → SMS-код на привязанный номер → новый пароль (≥ 6, дважды) → вход.

## Жизненный цикл смены и правила (сервер обязан проверять)
Этапы в «Моих сменах»: **Отклик → Найм → Работа принята** (отметки выхода/геометки **нет**, спора **нет**).

- **Откликнуться** нельзя: в роли работодателя; на отменённый / принятый / полностью набранный заказ; повторно. Если есть «своё условие» — исполнитель подтверждает его галочкой перед откликом.
- **Отказаться** (исполнитель): до найма — отзыв отклика; после — отказ от смены с причиной и сроком предупреждения (< суток = поздний отказ → пометка на 90 дней).
- **Нанять**: только работодатель своего заказа; не больше `crew`. При найме открывается чат, первое сообщение от работодателя: «Здравствуйте! Вы наняты на этот заказ. Подтвердите, пожалуйста, время выхода.»
- **Сделать старшим** — только в бригаде (crew > 1), только нанятого. Старший получает телефон встречающего и сдаёт работу за бригаду.
- **Отклонить** нельзя уже нанятого — для него «Не вышел».
- **Не вышел** снимает со смены **только этого** исполнителя (+1 к счётчику неявок), остальные остаются.
- **Сдать работу** (исполнитель): только после найма, не для отменённой/отказанной. После сдачи у работодателя **7 дней** на приёмку, иначе **автоприёмка** (засчитывается исполнителю).
- **Принять работу**: только если кто-то нанят и смена не отменена → открывается окно отзыва.
- **Отменить** (работодатель): нельзя принятую (подсказка «напишите в чат и оставьте отзыв») и уже отменённую. Отклики закрываются.
- **Перенести дату**: нельзя закрытую/отменённую; исполнители уведомляются.
- **Расчёт**: обе стороны отмечают «оплата передана» / «деньги получены» (информационно).
- **Отзыв**: после приёмки, обе стороны, 1–5 + текст; редактируемый ограниченное время.
- **Жалоба**: после приёмки; платформа разбирает поведение (пометка, понижение в выдаче, блокировка), деньги не возвращает.
- **Видимость**: адрес, доступ, инвентарь видны всем сразу; **телефон встречающего — только нанятому** (карточка смены, чат).
- Отменённые смены в «Моих сменах»: этапы зачёркнуты, кнопок действий нет, пояснение с причиной и датой.

## Модерация текста (запрещённые слова)
**Во всех текстовых полях** (заказ, чат, профиль, логин/никнейм, отзыв, жалоба, поиск): запрещённое слово **не даёт ввести** — поле откатывается к предыдущему значению, открывается попап «Так написать нельзя»: *Где* (название поля), *Что* (текст с выделенным словом, мат замаскирован `с••••а`), *Почему* (категория), кнопка «Исправить». Категории: нецензурная лексика, оскорбление, признак мошенничества. Дискриминация **не** фильтруется (решение заказчика).

Алгоритм — `normBad()`, `badWordIn()`, `BAD_WORDS`, `HARD_ROOTS` в исходнике:
- нормализация: lower, ё→е; два варианта — «похожие буквы» (a→а, c→с, x→х, y→у, 0→о, 3→з, 6→б, @→а …) и фонетический транслит (sh→ш, ch→ч, ya→я, h→х …); склейка через `* . _ -` и разрыв по ним;
- `BAD_WORDS` — корни с границами слова; `HARD_ROOTS` — корни, которые ловятся и внутри слова (склеенные ники `snowhuy`, `суперсука`) с исключениями против ложных срабатываний (`застрахуйте`, `оскорблять`, `употреблять`);
- тестовые наборы в истории: ловит `huy, blyat, suka, xyй, cyka, p1zda, Snow_huy, Mr.Suka, daniyarhuy, ivanblyat`; пропускает `Daniyar, Sergey, Shurik, Snow_Master, Pastukhova, Sukhov, сукно, небо, вебинар, хлебал`.
- **Обязательно дублировать проверку на сервере** (клиентскую легко обойти) и покрыть unit-тестами на эти наборы.

## Фильтры и поиск
Тип работы (поле с автодополнением по существующим типам, Enter — выбрать первый, Backspace — удалить последний), оплата от (слайдер 0–15 000 ₽, шаг 500), **расстояние от базы** (ступени 2/5/10/20/50/100/200/500 км/∞ + быстрые «до 10/50/200 км», «любое»), «когда выходить» (любые / сегодня и завтра), текстовый поиск. **Сезонов и регионов в фильтрах нет.** Счётчик «найдено N», метки активных фильтров с ×, «Снять всё». На сервере — гео-запрос по радиусу от base_lat/lng (PostGIS).

## Экраны
Все подробности, тексты и состояния — в прототипе. Список:
1. **Вход / регистрация / восстановление** — слева тёмная колонка (`--ink #22282e`): бренд «Арена Работы · каждая точка — работа», заголовок «Сезонная работа. / Смены на карте» (каждое предложение в одну строку), лид, строки «Карта / Отклик», счётчики исполнителей и работодателей (обновляются раз в сутки, из БД), справа форма. < 720 px — колонка скрывается.
2. **Карта** (главный) — шапка (логотип, «Создать профиль»/«Войти» или вкладки + чат + профиль, рекламные карточки 1–3 шт. по ширине), интро-полоса, тулбар (Все заказы списком · N, Фильтры, Журнал, Настройки), левая панель (гость: «Как это работает» с переключателем «Ищу работу / Нанимаю» и кнопкой «Создать профиль исполнителя/работодателя», партнёры), карта с группировкой меток, правая панель заказа.
3. **Карточка заказа** — условия, «Все условия заказа →» (памятка «До выхода»), работодатель (клик → профиль), кнопка отклика с единым статусом (отменён → вы наняты → закрыт → отклик отправлен → набрана → подтвердите условие → откликнуться), «Отказаться», блок смены (статус, **встречающий + телефон**, «Сдать работу»), приёмка, расчёт, оценка, жалоба, отмена, перенос, отклики с «Нанять / Отказ / Сделать старшим».
4. **Форма заказа** — 4 шага: Место → Работа → Деньги и время (календарь с «Сегодня/Завтра») → Доступ; валидация по шагам; черновик при закрытии («Продолжить / Удалить»).
5. **Мои смены / Мои заказы**, **Отклики**, **Чаты** (+ плашка «Сообщения» внизу), **Профиль** (карточка: фото, имя, город, навыки; разделы «Вход и контакты», «Свой инвентарь»/«Организация», «История смен», «Пометки площадки», «Договор» — шаблон ГПХ).
6. **Мобильная версия** — отдельный макет: карта + карточка + «все заказы списком ↑», лента, заказ, смена, чат, профиль, фильтры и журнал на весь экран, нижнее меню, рабочий режим. В прототипе: на ширине **< 720 px** открывается сразу во весь экран (без рамки, с учётом safe-area), на десктопе — в рамке iPhone на демо-вкладке. В продукте — адаптивная вёрстка по этому макету.
7. **Общее**: клик по логотипу — на главную (карта, закрываются панели). Макс. ширина контента: шапка/тулбар 1440 px, страницы (профиль, смены, чаты) 1280 px, карта — на всю ширину. Клик по затемнению закрывает боковую панель (журнал/настройки).
